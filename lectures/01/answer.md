## 宿題

- 取り組んだレベル：実装
- やったこと：`app/ask.py` に `--chat` オプションを追加し、同じSDKのChatを再利用して会話履歴を保持したまま続けて質問できるようにした。通常の単発質問は維持した。空行は送信せず、`/exit`、入力終了、Ctrl+Cで終了する。APIエラー時には説明を表示して次の入力を受け付ける。
- 使ったモデル：設定上は `gemini-3.5-flash-lite`（既定値）。`AIE_MODEL` で変更可能。APIキー未設定のため実モデルへの送信は未実施。
- 結果：ネットワーク呼び出しを置き換え、実際のgoogle-genai SDKのChatを使って履歴を検証した。2回目の送信内容が「最初のユーザー質問→モデル回答→次のユーザー質問」になることを確認するテストを追加した。実モデルの回答品質や実トークン数は未検証。
- 気づき・疑問：単発呼び出しを繰り返すだけでは前の文脈が渡らない。同じChatを使うと過去の質問と回答を次のリクエストに含められる。ただし履歴を持っても講座固有の正しい知識が増えるわけではない。履歴の増加に伴う入力トークン数や費用にも注意が必要である。会話履歴はメモリ上のみで、終了後には保存しない。
- AIツールの利用：Codexで実装とテストを作成した。確認済みのテストと未実施の実API検証を分けて記載した。

### 実行方法

```bash
uv sync --frozen
uv run python -m app.ask --chat "LoRAとは何ですか？"
```

続けて「今の説明を一文にまとめて」と入力する。`/exit` で終了する。APIキーは環境変数 `GEMINI_API_KEY` に設定し、コードや解答には記載しない。

### 確認方法

```bash
uv run pytest -q
```

`tests/test_ask.py` で会話履歴、空行の無視、終了処理、トークン数表示と使用量欠落時の表示を確認する。通信部分を置き換えたテストなのでAPIキーは不要。

確認結果：Python 3.12.14、固定依存関係で `uv run pytest -q` 相当の仮想環境から全テストを実行し、15件成功（15 passed）。実APIへの通信は行っていない。
