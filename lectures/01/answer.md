# 第1回 解答

## 講義で学んだこと（72文字）

基盤モデルを目的に合わせて適応させ、アプリを構築する考え方を学んだ。AIの出力を鵜呑みにせず、人が検証し、評価と改善を継続する重要性を理解した。

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約）：宿題を難易度別に選ぶ形式として、レベル1を基礎・初級、レベル2を応用・中級、レベル3を発展・上級と説明した。また、プロンプトの段階を指す可能性も提示し、講座資料で確認するよう案内した。
- 用語集の正しい意味と比べて気づいたこと：`data/glossary.json` の正解は「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」で、どれか1つに取り組めば完了となる。モデルは「実装」を「応用・中級」として一般化し、複数の可能性を挙げた。講座固有の情報は、もっともらしい説明でも資料と照合する必要がある。
- 表示できたトークン数（入力 / 出力）：LoRAの最初の質問では7 / 625、続く要約の質問では639 / 48。`usage_metadata.prompt_token_count` と `candidates_token_count` を表示した実測値である。

## 宿題

- 取り組んだレベル：実装
- やったこと：`app/ask.py` に `--chat` オプションを追加し、同じSDKのChatを再利用して会話履歴を保持したまま続けて質問できるようにした。通常の単発質問も維持した。空行は送信せず、`/exit`、入力終了、Ctrl+Cで終了する。APIエラー時には説明を表示して次の入力を受け付ける。
- 使ったモデル：`gemini-3.5-flash-lite`。GitHub Codespacesに保存した `GEMINI_API_KEY` を使って実行した。
- 結果：2026年11月2日、Codespacesで実APIを呼び出し、単発質問と会話履歴を使う連続質問の両方で回答を受信した。最初に「LoRAとは何ですか？」と質問し、続けて「今の説明を一文にまとめて」と入力したところ、前の文脈を踏まえ、モデル全体を書き換えず少数の追加パラメータを学習する技術としてLoRAを一文で説明した。`/exit` で正常に終了した。
- 気づき・疑問：同じChatを使うと過去の質問と回答を次のリクエストに含められる。追加の質問自体は短いが、入力トークン数は7から639に増えており、履歴を送る影響を確認できた。ただし履歴を持っても講座固有の正しい知識が増えるわけではない。会話履歴はメモリ上のみで、終了後には保存しない。
- AIツールの利用：Codexで実装とテストを作成し、テスト結果と実APIの応答を確認した。

### 実APIでの確認結果

| 順番 | 質問 | 回答の概要 | 入力トークン | 出力トークン |
|---|---|---|---:|---:|
| 1 | LoRAとは何ですか？ | LoRAの仕組み、効率性、主な用途を説明 | 7 | 625 |
| 2 | 今の説明を一文にまとめて | 前のLoRAの説明を一文に要約 | 639 | 48 |

この数値は1回の会話で得た実測値であり、実行ごとに変動する。

### 実行方法

```bash
uv sync --frozen
uv run python -m app.ask
uv run python -m app.ask --chat "LoRAとは何ですか？"
```

続けて「今の説明を一文にまとめて」と入力する。`/exit` で終了する。APIキーはCodespaces secret `GEMINI_API_KEY` から環境変数として渡す。

### 自動テスト

```bash
uv run pytest -q
```

Python 3.12.14、固定依存関係を使ったローカル環境で全15件成功（15 passed）。`tests/test_ask.py` では通信を置き換え、実際のSDKのChatで「前の質問→モデル回答→次の質問」が送信されること、空行の無視、終了処理、使用量表示を確認した。
