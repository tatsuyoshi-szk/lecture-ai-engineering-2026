## 宿題

- 取り組んだレベル：実装

### 変えた設定やデータ

元の講座FAQを、架空の図書館の利用案内5項目に置き換えた。`FAQ`、`GROUNDED`、`UNGROUNDED` に加え、test専用の追加質問とセクション6の質問も題材に合わせて変更した。JSONのキー `answer` と `needs_review`、FAQに根拠がなければ確認を求める設計、モデルと学習設定は元のままとした。

| FAQ項目 | 内容（すべて架空） |
| --- | --- |
| 貸出冊数 | 1人につき5冊まで |
| 貸出期間 | 貸出日から14日間 |
| 平日の開館時間 | 10:00〜18:00 |
| 返却場所 | 館内の返却カウンター、または入口の返却箱 |
| 貸出延長 | 予約がない本に限り、1回だけ7日間 |

根拠ありの質問には、同じ項目を尋ねる複数の言い換えを用意した。学習・検証・評価で質問文が重複しないように分割し、testには根拠あり15問、根拠なし6問を用意した。正解の `needs_review` と必須語句は採点用に分離し、推論時の入力には渡していない。

「根拠なし」の質問は、FAQに記載がなく、記載済みの項目からも答えを推論できない事柄を選んだ。例えば、延滞料金、学習室の予約方法、図書館の住所、購入リクエスト、他館からの取り寄せなどである。また、平日の開館時間から祝日の開館時間を決めつけないかを確認するため、祝日の時間も評価質問に含めた。無線LANやカード再発行などの学習用質問とは、評価用の質問文を分けた。

### 結果（比較表や数字）

同じ21問、同じ生成設定で学習前後を比較した。

| 指標 | 学習前 | 学習後 |
| --- | --- | --- |
| 形式遵守率（format_rate） | 14.3%（3/21） | 100.0%（21/21） |
| 内容正解率（content_rate） | 4.8%（1/21） | 95.2%（20/21） |
| 形式・内容の両方が正解（both_rate） | 4.8%（1/21） | 95.2%（20/21） |
| 評価にかかった時間 | 33.8秒 | 38.3秒 |

上の時間は21問への回答生成と評価の所要時間であり、LoRAの学習時間ではない。

学習前は18問で `needs_review` が欠けていた。例えば「同時に借りてよい本の冊数は？」には `{"answer": "1 冊"}` と返したが、学習後は `{"answer": "本の貸出冊数は、1 人につき 5 冊までです。", "needs_review": false}` と返せた。

学習後は根拠なし6問すべてで確認要求を正しく返した。根拠あり15問は14問が正解し、返却カウンター以外の返却場所を尋ねる1問だけが誤った確認要求になった。学習前に形式・内容の両方を満たしていた質問が学習後に失敗する退行はなかった。

内容正解率には `needs_review` の一致と必須語句の包含が必要である。学習前にも文面が正しい回答はあったため、内容正解率の上昇をそのまま知識量の増加と解釈することはできない。

### ファインチューニングが向く場面・向かない場面についての考察

今回、形式遵守率が100%になったことから、決められたキーを含むJSON出力や、確認を求める際の定型文など、繰り返し使う回答の振る舞いを揃える用途に向いていると考える。

一方、形式が正しくても、FAQに記載された返却箱の情報を使えず、確認要求に逃げた例が残った。したがって、形式を学習できたことだけで、根拠の有無を常に正しく判断できるとはいえない。今回の入力には毎回FAQが含まれるため、この実験だけでは新しい知識をモデル内部に獲得したとも判断できない。

住所やイベント日程など、未知の事実や更新される情報に対応する場合は、正しい資料を入力に渡す、またはRAGで検索して渡す方法が適していると考える。その場合も読み落としは起こり得るため、根拠あり・根拠なしの両方を評価する必要がある。今回は5項目のFAQと21問による1回の実験なので、別の言い換えや別のFAQでも同じ性能が出るかは追加検証が必要である。

AIツールはデータ案の作成、エラーの解決、結果整理と文章作成の補助に使用した。学習と評価は自分のColabで実行し、数値と回答例は保存された実行結果に基づいて記載した。
